# 物流售前现场调研工具 · 立项说明

> 版本：v0.1（立项稿）
> 定位：售前体系中的「现场调研采集入口」
> 维护：桂中海迅 · 售前/项目组

---

## 一、为什么做（背景）

3PL 外包项目的售前，第一步永远是**现场调研**：看仓库、问用工、记瓶颈、拍现场。目前这一步存在三个问题：

1. **靠老顾问个人经验**——问什么、记什么没有标准，新人去了容易漏关键信息。
2. **现场记录零散**——纸笔 + 手机相册 + 脑子记，回来整理耗时且容易失真。
3. **成果不规整**——交给后端测算（人数/成本/毛利/报价）时，数据口径不统一，要反复返工对齐。

我们已经在实际项目（汽配仓储调研）中验证过：用一个手机版调研工具现场边走边填、当场出报告，是非常高效的方式。本次立项就是把这个一次性工具，**固化成团队常态化使用的标准采集器**。

## 二、做什么（产品定位）

> **一句话：现场调研采集器——把现场的事记全、记准，当场出图文调研报告。**

这个工具**只负责采集与出报告**，不负责算账、不负责对接系统：

```
现场调研采集器  ──出图文报告──►  ① 人看（团队/客户）
（本工具）                      ② 喂给 Logistics Presale System
                                  （由该系统完成人数/成本/毛利/报价测算）
```

### 在售前体系中的位置

| 环节 | 由谁负责 |
|---|---|
| 现场调研、拍照、记录、出调研报告 | **本工具（立项对象）** |
| 人数测算、成本/毛利、报价、SLA/KPI 方案 | Logistics Presale System（已有，不在本次立项范围） |
| 数据流转 | 复用 Presale System 已有的 NotebookLM 导入能力，本工具只需输出 NotebookLM 友好的报告 |

## 三、范围边界（关键）

明确"做"与"不做"，避免和 Presale System 职责重叠。

### ✅ 本工具要做

- **结构化字段采集**：仓储货物概况、用工现状、瓶颈环节、空间结构、现场观察等客观事实
- **拍照记录 + AI 图注**：现场拍照、按板块归类、自动/手动生成图注（核心能力，重点打磨）
- **一键出调研报告**：图文 Markdown + 图文 ZIP 打包，作为现场成果物
- **本地自动保存**：数据存浏览器本地，断网也能用

### ❌ 本工具不做（归 Presale System）

- 人数、用工成本、毛利、报价的任何**计算**
- 投资回收期、ROI 等**测算**
- 与 Presale System 的**接口对接**（复用其 NotebookLM 导入即可）
- 云端账户、多人协作、历史项目库（如有需要列入后续版本，非本次范围）

> 商务/测算类信息（如期望计费方式、预算、报价时间）在工具里**只作记录**，现场问到就记一笔，工具不做任何运算。

## 四、现有基础（不是从零开始）

汽配仓储项目已沉淀一个可用原型 `汽配仓储调研.html`，本次立项以它为 v1.0 底座：

| 已具备 | 说明 |
|---|---|
| 7 大调研板块 | 项目基础 / 仓储货物 / 用工外包 / 自动化改造 / 现场观察 / 商务决策 / 结论 |
| 移动端优化 | 手机浏览器即用，可加主屏，离线可用 |
| 拍照 + AI 图注 | 现场拍照、调用 AI 生成图注 |
| 本地自动保存 | localStorage，换页不丢 |
| 报告导出 | Markdown 单文件 + 图文 ZIP 包 |

## 五、本次立项要做的事（v1.0 打磨）

不是重做，是按新定位收口：

1. **强化拍照/图注体验**——按板块归类照片、现场标注、图文报告排版优化。
2. **测算字段降级为纯记录**——保留商务/预算字段但移除任何计算逻辑，职责交给 Presale System。
3. **报告可读性 + NotebookLM 友好**——报告结构清晰、信息密度高、便于 NotebookLM 提炼。
4. **通用化收口**——字段尽量适配不同行业仓（汽配/工程机械/电商/医药/快消），通过保留通用项实现。

## 六、里程碑

## 七、投入估算

定位收敛后投入很轻：

- 工具改造：以现有原型为底座，工作量小
- 无服务器/云成本（纯本地 HTML）
- AI 图注：复用现有 API（按调用量计，成本极低）

## 八、风险与对策

| 风险 | 对策 |
|---|---|
| 数据只存本地，换设备/清缓存会丢 | 现场调研后立即导出报告归档；后续版本视需要再上账户体系 |
| AI 图注需联网 | 无网时手填图注照常工作，不阻塞调研 |
| 报告格式与 NotebookLM 导入不完全契合 | 先按通用 Markdown 输出，实际导入跑通后再微调结构 |
| 字段做太宽反而难用 | 通用字段为主、行业差异项按需增减，避免一次性堆满 |
