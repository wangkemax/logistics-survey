# v1.0 开发规格

> 目标：把汽配仓储项目的一次性原型 `tools/汽配仓储调研.html`，按"纯现场调研采集器"定位收口为 v1.0。
> 原则：以改造为主，不重写。每个任务都给了验收标准。

---

## 任务 1 · 强化拍照 / 图注体验（重点）

**现状**：原型已能拍照 + 调 AI 生成图注、ZIP 导出。
**要做**：
- 照片**按调研板块归类**（每张照片可归到"仓储货物/用工/瓶颈/现场观察"等板块）
- 支持**现场手动标注**（至少：每张照片可加文字图注；标注 UI 触控友好）
- 报告里照片与对应板块**图文穿插**，而不是全堆在末尾
- 批量拍照、从相册多选、删除/重排

**验收**：现场拍 10 张照片，分别归到不同板块，导出的报告里每张照片出现在对应板块下、带图注。

## 任务 2 · 测算字段降级为纯记录

**要做**：
- 通读字段，凡涉及**计算结果**的（自动算人数、成本、毛利、回收期等）一律移除计算逻辑
- 商务/预算类字段（计费方式、预算范围、报价时间、回收期期望等）**保留为纯输入/记录**
- 检查 JS，删掉任何做算术汇总/推导的函数

**验收**：全工具内搜不到为业务测算服务的计算函数；预算/计费等字段填了只是被原样记录进报告。

## 任务 3 · 报告可读性 + NotebookLM 友好

**要做**：
- Markdown 报告结构清晰：标题层级规整、表格对齐、空字段不输出杂乱占位
- 信息密度高、表述完整（便于 NotebookLM 提炼，避免大量空表头和"—"）
- 报告头部含项目元信息（客户、地址、调研人、日期），便于检索
- 图文 ZIP 内：报告 .md + 照片，图注与照片对应清楚

**验收**：导出的 Markdown 直接可读、可丢进 NotebookLM；空板块/空字段不产生噪音。

## 任务 4 · 字段通用化收口

**要做**：
- 复核 SCHEMA，把"汽配专属"措辞改为**通用仓储**措辞，差异项做成可选/可增减
- 货物类型、存储方式、瓶颈环节等多选项覆盖常见行业（汽配/工程机械/电商/医药/快消）
- 保持精简——通用项为主，不要一次堆满所有行业的长尾字段

**验收**：拿一个非汽配场景（如电商仓）走一遍，字段够用、无明显汽配专属错配。

---

## 通用要求（贯穿所有任务）

- **不破坏离线能力**：断网时除 AI 图注外全部可用；AI 图注无网时降级为手填。
- **localStorage 兼容**：改 SCHEMA 时做好 key 版本管理，别让用户已填数据丢失。
- **单文件**：所有改动保持在一个 HTML 内。
- **视觉一致**：沿用原型的风格，不要换主题。

## 明确不做（再次强调）

- 不加任何业务测算 / 报价 / ROI 计算
- 不做服务端 / 账户 / 云同步
- 不做与 Presale System 的接口对接
